# Пьяное караоке · Drunk Karaoke — памятка для агентов

Локальная караоке-игра. Мелодия и ритм настоящей песни остаются нетронутыми, а слова
заменяются **целыми записями** из постороннего датасета: названиями товаров, побочными
эффектами из инструкции к лекарству, объявлениями с доски. Человек поёт их под знакомую
мелодию — в этом вся шутка.

Всё работает локально: ни LLM, ни нейросетей, ни API-ключей, ни запросов наружу.
Подбор текста — детерминированный JavaScript в браузере.

## Запуск и проверка

```sh
npm run library                      # индексировать папки с песнями UltraStar
npm run backdrops                    # скачать фоны с Викисклада (один раз)
npm start                            # http://127.0.0.1:4173/
npm test                             # 13 тестов движка и разбора разметки
npm run check -- dist/data/ads.txt   # проверить датасет
```

**Перед коммитом любых правок движка гоняй `npm test`.** Тесты сторожат инварианты,
которые легко сломать незаметно.

## Нерушимые правила

Их нарушение убивает игру, даже если код формально работает.

1. **Запись неделима.** Единица подстановки — целая строка датасета. Её нельзя резать,
   переставлять внутри, дополнять словами или склеивать из кусков. Любой обрывок посреди
   мысли — это провал.
2. **Слогов ровно по нотам.** Строка песни из 14 нот получает ровно 14 слогов. Это жёсткое
   условие, а не пожелание.
3. **Ничего не выдумывается.** Каждое слово дословно из датасета, с точными координатами.
4. **Повторяющиеся строки песни получают один и тот же текст.** Припев остаётся припевом.
5. **Ударения — судья, а не генератор.** Они выбирают между валидными вариантами, но никогда
   не разрешают нарушить правила 1–3.
6. **Никаких сетевых запросов в рантайме игры.** Сеть используют только скрипты сборки.

## Как собирается строка

1. Датасет режется на записи: файл-список — одна запись на строку, разделы через `## Заголовок`.
   Проза режется по знакам препинания на законченные клаузы.
2. Для каждой длины строки песни движок **сэмплирует комбинации** из 1–4 целых записей, сумма
   слогов которых точно равна числу нот. Таблица достижимости `feasible[k][rest]` гарантирует,
   что выборка никогда не заходит в тупик.
3. Комбинации оцениваются и лучшие идут в beam search по всей песне (рифма с одной из четырёх
   предыдущих строк, неповторное использование записей).
4. **Протяжные ноты.** Нота длиннее `LONG_NOTE` (0.9 с) — это место, где вокал тянут на одной
   гласной. Движок сравнивает саму гласную (я→[а], ё→[о], е→[э], ю→[у]) и проверяет, можно ли
   слог вообще протянуть: «крем-брюле» тянется, «кинетический песок» — нет. На реальной песне
   совпадение гласной выросло с 3% (случайность) до ~52%.

### Оценка комбинации

```
−3.5 × расхождение ударений
+1.6 × доля протяжных нот с совпавшей гласной
−0.9 × доля протяжных нот на непротяжном слоге
+0.55 × рифма            −0.9 × то же последнее слово
−0.7 × доля неизвестных ударений
−1.8 × повторное использование записей
−0.7 × одинаковое первое слово у соседей   («Пицца … · Пицца …»)
−0.3 × соседи из одного раздела
+0.25 × записи оказались соседями в файле
−0.12 × записи сверх трёх
```

Веса подобраны замерами, а не на глаз. Если меняешь их — замеряй заново: расхождение
ударений, долю совпавших гласных на длинных нотах, число разных версий на 40 seed.

## Разбор UltraStar: чего не ломать

Парсер чинит реальные файлы, а не требует идеальных. Каждая мера появилась из-за конкретной
поломки на коллекции из 169 папок:

- **Хвостовые пробелы значимы.** Часть чартов помечает границу слова пробелом в конце слога,
  а не в начале. Нельзя делать `trimEnd()` на строке нот — это склеивает всю строку в одно
  слово и теряет все ударения в ней. Эта ошибка стоила 53% всех пропущенных ударений.
- Ноты с несколькими гласными делятся на слоги с пропорциональным таймингом.
- Ноты без гласных приклеиваются к соседнему слогу.
- Дуэты `P1`/`P2` сводятся в одну дорожку, дубли партий отбрасываются.
- Латинские двойники кириллицы внутри русских слов чинятся.

Итог: 167 папок из 169. Не разбираются только англоязычные — для них нужен CMUdict.

## Словарь ударений

`dist/data/dictionary.json` — словоформы OpenRussian (CC BY-SA 4.0).
`dist/data/accents.txt` — **наше дополнение, которое важнее словаря.** Туда идёт всё, чего
OpenRussian не знает или знает неверно. Важно: в OpenRussian нет склонения местоимений, поэтому
«тобой», «нами», «него» без дополнения остаются без ударения.

Формат: одна словоформа в строке, знак ударения `U+0301` после гласной, `#` — комментарий.

## Экспорт

Звук сводится офлайн (`mixSong`), **громкость минусовки в транспорте — она же мастер сведения**:
насколько приглушил музыку при пении, настолько она приглушена в файле.

Ролик пишется **в реальном времени** — иначе браузер не отдаст видеодорожку: кадры рисуются на
canvas по часам того же `AudioContext`, из которого играет сведённый буфер, поэтому картинка не
уезжает от музыки. `canvas.captureStream` + дорожка из `MediaStreamAudioDestinationNode` идут в
`MediaRecorder`. Формат выбирается по `MediaRecorder.isTypeSupported`: MP4 (H.264+AAC), иначе WebM.

При правке рендера помни: разделитель `·` между записями в canvas надо рисовать руками — в DOM
это `::before`, и без него строка склеивается в один неразрывный кусок и вылезает за кадр.
