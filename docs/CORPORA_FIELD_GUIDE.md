# Полевой справочник по корпусам Robot Karaoke

Этот файл передаёт практические находки следующему специалисту, который будет искать,
собирать или чинить корпуса. Это не замена `docs/DATASETS.md`: здесь собраны именно
неочевидные решения, ошибки и рабочие приёмы, обнаруженные на реальных выгрузках.

## Главный принцип

Корпус должен быть одновременно:

1. реальным — каждая строка приходит из открытого источника, а не сочиняется вручную;
2. абсурдным в столкновении с песней — инструкции, отзывы, юридический язык и каталоги
   смешнее универсальных «рандомных фраз»;
3. играбельным — законченная строка, известные ударения, преимущественно 8–16 слогов.

Смешивать источники можно только как явное дополнение. В метаданных и в документации
нужно сохранять, откуда пришла каждая группа строк.

## Что особенно хорошо сработало

### Реальные источники

- Яндекс Карты и публичные страницы меню дают живой материал, но HTML нестабилен: нельзя
  рассчитывать на вечные CSS-классы. Скрипт должен сохранять снимок локально, а игра не
  должна обращаться к сети.
- `chipslays/russian-recipes-parser` — удобный MIT-снимок: JSON-рецепты с названием,
  описанием и шагами. Названия блюд обычно уже подходят по длине.
- Open Food Facts — хороший источник названий и составов, но API может медленно отвечать
  или временно дросселировать запросы. Делать повторные попытки, сохранять частичный
  снимок и не считать количество API-записей гарантированным.
- SortBase ценен не объёмом, а необычными названиями сортов и гибридов. Для семян
  абсурдные брендовые названия важнее сухой полноты реестра.
- XML юридических актов требует извлекать предложения из `<s>` и склеивать содержимое
  `<w>`, предварительно декодируя числовые HTML-сущности вроде `&#1054;`.

### Разделение похожих корпусов

Названия товаров и отзывы Wildberries — два разных корпуса. Товары дают каталожную
абсурдность, отзывы — живую речь. Их нельзя незаметно объединять: это меняет характер
игры и ломает проверку происхождения строк.

Текущая выборка `ali.txt` в игре называется «Товары из маркетплейсов»: это 15 037
цельных названий карточек Wildberries, не перевод AliExpress. Латиница
транслитерирована, числительные записаны словами, все ударения проходят проверку.
86% записей имеют 8–16 слогов. Игровой корпус отобран из 217 000 локально сохранённых
карточек: прежнего снимка и первых 200 000 строк открытой выгрузки Wildberries.
Для следующих каталогов сохранять целые названия и проверять ударения; короткие
названия оттенков не использовать как самостоятельные записи.

### Газетные заголовки Gazeta.ru

`gazeta.txt` собран только из колонки `title` открытого набора IlyaGusev/gazeta: 25 025
цельных строк, медиана 12 слогов, ядро 8–16 слогов — 71%. Числа записаны словами,
латиница транслитерирована, неизвестные многосложные слова исключены. Заголовки не
режутся на предложения и не смешиваются с колонками текста или summary. Источник
ограничивает использование личными некоммерческими целями.

## Числа: самая опасная часть очистки

Нельзя заменять цифры посимвольно. Так `23 ноября` превращается в «два три ноября», а
`23.11.2025` — в поток цифр. Правильный порядок преобразований в `digitsToWords`:

1. даты `день месяц` и `дд.мм.гггг`;
2. проценты;
3. диапазоны `2–3 недели` и OCR-вариант `2 3 недели`;
4. десятичные числа;
5. числа с пробелом тысяч `1 000`;
6. обычные целые числа.

Для диапазонов нужен дефис или другая сохранённая граница (`два-три`), иначе финальная
очистка снова склеит их в «два три». Контекст важен: дата использует порядковый падеж,
размер — порядковую форму, количество — количественную.

После любого изменения числительных искать не только цифры, но и следы плохой замены:

```sh
rg -n --glob '*.txt' 'один ноль|два три|три ноль|пять ноль|ноль ноль' dist/corpora
```

Некоторые последовательности вроде `один два три четыре` являются настоящими рядами из
источника и не должны автоматически удаляться. Проверять нужно контекст.

## Очистка и отбор строк

- Сначала чистить HTML, URL, служебные атрибуты и латиницу; затем преобразовывать числа.
- Латиницу транслитерировать, а не молча выкидывать: в исходных данных встречаются бренды,
  названия технологий и `Stack Overflow`.
- Делить прозу по знакам препинания только на законченные клаузулы. Не сохранять обрывки
  вроде «и в случае если».
- Удалять дубликаты без учёта `ё/е` и повторных пробелов.
- Фразы с неизвестными словами не «чинить» выдуманными ударениями: либо добавить слово
  в общий словарь после проверки, либо исключить строку.
- `sampleRows` должен сохранять небольшую долю коротких строк для добора слогов, но ядро
  корпуса держать в диапазоне 8–16 слогов.

## Формат файла

Для выгрузок и каталогов использовать:

```text
---
name: Понятное название
about: Откуда и что именно собрано
mode: list
---

## Смысловой раздел
Одна строка — одна неделимая запись
```

`mode: list` обязателен для строк, которые нельзя разрезать на отдельные слова. Разделов
обычно нужно 8–10, и они должны отличаться словарём, а не только названиями.

## Ударения

Общий словарь — источник нормы. Локальный раздел `## ~ударения` допустим как временный
перевалочный пункт для внешнего файла, но после этого нужно выполнить:

```sh
npm run accents
npm run accents -- --apply
```

После применения новые ударения должны оказаться в `dist/data/accents.txt`, а временный
раздел — исчезнуть из корпуса. Если корпуса расходятся в ударении, решение нужно записать
явно в `RESOLVED` скрипта, а не прятать в случайной обработке.

## Рабочий цикл

1. Сохранить исходный файл в `.corpus-source/` до перезаписи (`*-base.txt`).
2. Написать или обновить офлайн-скрипт получения снимка.
3. Собрать корпус через `scripts/build-real-corpora.mjs`.
4. Обновить индекс: `npm run corpora`.
5. Проверить ударения: `npm run accents`.
6. Запустить `npm test`.
7. Проверить `git diff`, особенно удаление/переименование файлов и документацию источников.

Сборка использует большие выгрузки и может занимать несколько минут. Не запускать несколько
сборок параллельно: они одновременно перезаписывают `dist/corpora` и манифест.

## Типичные ловушки

- API может вернуть HTTP-успех с неполным или медленно читаемым JSON. Нужны таймаут,
  повторы и локальный снимок.
- В XML и HTML встречаются числовые сущности, кавычки и неразрывные пробелы.
- Телефоны, артикулы, КБЖУ и технические коды не всегда являются обычными числами. Их
  нужно либо распознавать по контексту, либо исключать как непевучие.
- Слишком много коротких названий меню ухудшает связность: генератор начинает склеивать
  несколько блюд. Иногда лучше оставить короткие строки хвостом и убрать избыток точных
  совпадений с длинами тестовой песни.
- После удаления корпуса нужно запускать `npm run corpora`: индекс строится по фактическим
  `.txt`, а не по документации.
- Тесты, жёстко привязанные к конкретному корпусу, надо либо переводить на устойчивую
  фикстуру, либо явно пропускать после осознанного удаления этого корпуса.

## Команды контроля

```sh
npm run corpora
npm test
npm run accents
rg -n --glob '*.txt' '[0-9A-Za-z]' dist/corpora
rg -n --glob '*.txt' 'один ноль|два три|три ноль|пять ноль' dist/corpora
```

Последние две проверки не заменяют тесты, но быстро ловят цифры, латиницу и испорченные
диапазоны после нового источника.
